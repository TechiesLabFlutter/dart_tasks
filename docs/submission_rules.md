# Submission rules

## Location

Your work goes in one place only:

```
submissions/<your_name_folder>/<task_name>.dart
```

The folder already exists and carries your name. Do not create another one, and do not create folders inside it.

## File names

`<task_name>` is copied exactly from the folder name used in `tasks`. Same spelling, same lowercase letters, same underscores.

If the task folder is `grade_classifier`, your file is `grade_classifier.dart`. It is not `Grade Classifier.dart`, not `grade classifier.dart`, not `task2.dart`, not `main.dart`.

A file named after something else is easy to miss during evaluation, and a missed submission is a lost grade.

## What to upload

Upload your source code and nothing else.

Do not upload:

1. Generated folders such as `build` and `.dart_tool`.
2. Editor settings such as `.idea` and `.vscode`.
3. Screenshots, videos, or archives, unless the task asks for them.
4. Compressed files. Upload the real file, not a zip.
5. Any file that contains a password, a token, or an API key.

## Other people's folders

Never open, edit, or delete a file inside another participant's folder. Everything you do here is recorded with your name on it.

## Deadlines

Each task description carries its deadline. Your submission time is the time of your upload, and GitHub records it automatically.

A late submission is still worth uploading. A missing submission is worth nothing.

## Honesty

You may read the documentation, search the internet, and ask for help. Copying another participant's code and presenting it as your own is not accepted.

You will be asked to explain your own code during the sessions. If you cannot explain it, the score is adjusted regardless of whether the code runs.
